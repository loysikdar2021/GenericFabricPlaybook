Authoring style guide

Every page in this site is plain HTML that uses one stylesheet and one script. This page is both the contract for contributors and a live gallery of every component, including the diagram vocabulary.

  • Audience contributors
  • Build step none
  • Diagrams inline SVG

Page skeleton

Navigation, sidebar, table of contents, previous/next links and footer are generated by assets/js/site.js from assets/js/site-data.js. A page only supplies its own content inside <main id="main">. Set data-root to the relative path back to the site root (../../ for pages under playbooks/<id>/).

Rules the validator enforces

Exactly one <h1> per page; an id on every <h2> and <h3> (they become search anchors); every internal link and #anchor must resolve; every <svg> must sit in a <figure class="diagram"> with a <figcaption>. Run python tools/validate_site.py before committing.

Diagram vocabulary

Diagrams are hand-authored inline SVG so they render offline, follow the light/dark theme and can be diffed in Git. A diagram earns its place when it shows a mechanism the reader would otherwise assemble from prose: where data flows, what changes between two options, what state something moves through. If a sentence says it faster, write the sentence.

  • Classes, not colours. Put class="dg" on the <svg>. Shapes use box plus a hue (blue teal green orange red purple gray bronze silver gold accent); containers use zone (dashed) or lane; lines use ln (dash thick thin plus a hue); text uses t t-b t-h t-s t-m t-w.
  • Label the arrows with a verb (ingests, invokes, publishes). Back long labels with a pill-bg rect so lines do not strike through text.
  • Unique ids. Prefix marker ids with the figure id (fig-ingest-a) because all inline SVGs share one document.
  • Size by viewBox, 760–900 units wide and as short as the content allows (the page column is about 900px, so wider drawings render their text small). Text is 11–13 units; keep labels to a few words and move prose to the caption. t-w is the text colour for labels on a box accent fill.
  • No <style>, <script>, <foreignObject>, images or hard-coded hex colours. Avoid transform except simple translate.
  • Every figure has role="img", an aria-label that states the claim, and a <figcaption>.

Content rules

  • Vendor-neutral and client-neutral. Use placeholders such as <DOMAIN>, contoso, 00000000-0000-0000-0000-000000000000. No real tenant names, workspace names, user names, e-mail addresses, screenshots or dates of engagements.
  • No date stamps. Do not write months, years or "as of" phrasing. Where status changes (preview, limits), say check current status and link the Microsoft Learn article.
  • Link primary sources. End each page with a <section class="refs"> of Microsoft Learn links without a locale segment (learn.microsoft.com/fabric/...).
  • Be specific. Prefer a decision table, a worked example or a runnable snippet over general advice; explain the trade-off, not just the recommendation.
  • Make code copyable. Parameterise names, keep cells self-contained and note the language and where it runs.
