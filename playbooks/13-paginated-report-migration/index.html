Paginated Report Migration

Paginated reports are the print-ready, pixel-controlled reports built from RDL files. This playbook moves them from workspaces on Power BI Premium capacity to workspaces on Fabric capacity, with the same reports, the same data and no surprises for the people who open them on Monday morning.

Purpose and scope

Paginated reports do not hold data. Each report is a layout plus queries that run at render time against the sources it names, which makes a migration mostly a question of where the report lives, which capacity runs it and how it reaches its data. This playbook covers all three:

  • Where it lives. Keep the legacy workspace and change its capacity, or publish the RDL files into new development, test and production workspaces governed by a deployment pipeline.
  • Who runs it. Move from a Premium (P) capacity to a Fabric (F) capacity, which sets who can view the reports without a paid license and how much concurrent rendering you can serve.
  • How it reaches data. Rebuild the data source mappings, credentials and gateway bindings for each environment, including Fabric Warehouse and Lakehouse SQL analytics endpoints as new sources.

The three phases

  1. AssessInventory every report, its sources, parameters and features; decide each report's fate.
  2. MigrateReassign the workspace or republish the RDL files; recreate credentials and gateway bindings.
  3. PromoteApply data source rules so each stage reads its own sources.
  4. ValidateProve layout, data, exports, performance, subscriptions and access match.
  5. Cut overSwitch users, keep a rollback, then retire the old capacity.

When to use this playbook

Use it when

  • Paginated reports live in workspaces assigned to Power BI Premium capacity and the capacity is going away.
  • You are standardising on Fabric workspaces named by environment, with promotion through a pipeline.
  • Reports come from SQL Server Reporting Services or Power BI Report Server and must land in the Power BI service.

Look elsewhere when

  • You are moving Power BI reports and semantic models, not RDL files: use Power BI to Fabric migration.
  • You need general promotion mechanics for Fabric items: use Deployment pipelines.
  • You are building interactive reports: use Power BI report development standards.

Before you start

  • A Fabric (F SKU) capacity exists, sized from the Premium capacity it replaces, with capacity administrators assigned. See the sizing notes on the migration methods page.
  • You can publish: a Power BI Pro or Premium Per User license is needed to publish paginated reports to workspaces other than My workspace, and the publisher needs at least the Contributor role in the target workspace.
  • You know who owns each report. Data source rules, take-over and credentials all depend on the identity that owns the item.
  • On-premises sources have a gateway, and someone with gateway admin rights can add data sources to it.
  • Power BI Report Builder is installed for the people who will edit RDL files, and everyone uses the same version.

Check who can view the reports after the move

Users with a free license can view paginated reports only in workspaces on a Fabric capacity of F64 or larger, or a Premium capacity of P1 or larger. On smaller Fabric capacities, every viewer needs a Power BI Pro or Premium Per User license. If your audience relies on free licenses, do not size the target below F64. The mapping from P SKUs to F SKUs is on the methods page.

Paginated reports that read from semantic models inherit the standards in Power BI report development.

Key takeaways

  • A paginated report has no data of its own, so migration is about location, capacity and connectivity.
  • Decide per workspace between reassigning and republishing; both leave a way back until you retire the old capacity.
  • Size the target at F64 or larger if free-license users must keep viewing the reports.
  • Plan for credentials and gateway bindings to be recreated; moving the RDL does not move them.
  • Finish with parity tests and a recorded rollback, not with a setting change.
