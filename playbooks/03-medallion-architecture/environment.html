The Environment item

An Environment item is the execution contract for a layer: the runtime, Spark properties, compute sizes and libraries that every notebook in that workspace runs with. Set it once as the workspace default and the setup snippets disappear from notebooks.

  • Audience platform and data engineers
  • Focus Spark configuration

What the Environment item is

An Environment is a workspace item that defines Spark session configuration for notebooks and Spark job definitions. You can run without one, using the workspace-level Spark settings, but an Environment makes the configuration reusable, governed and versionable as a single artifact. It replaces the session-builder snippet that otherwise gets pasted at the top of every notebook, where it drifts.

ComponentContainsTakes effect
Spark computeThe Spark runtime, the pool (starter pool or a custom pool), driver and executor cores and memory, and Spark propertiesOn save and publish
LibrariesPublic libraries from PyPI or Conda and custom libraries you upload, such as wheelsOn save and publish
ResourcesSmall files that attached notebooks can readImmediately; resources are not part of publishing

In this playbook each layer workspace carries one Environment named ENV_<DOMAIN>_<LAYER>_<Function>, for example ENV_SALES_SLV_Spark, set as that workspace's default. Layers differ in what they need: Bronze ingests, Silver merges, Gold feeds Direct Lake and SQL readers, and a per-layer Environment lets each have its own runtime, profile and libraries without per-notebook overrides.

Who can change the default

After an environment is set as the workspace default, only workspace admins can update its contents. That is useful for governance, and it means changes to a layer's runtime or libraries go through whoever administers the layer's workspace.

Choosing a runtime

The runtime sets the Spark and Delta Lake versions, the operating system and the preinstalled libraries. The environment pins it, so a change of runtime is an explicit, reviewable change that you publish and promote like any other.

RuntimeApache SparkDelta LakeConsider it when
1.33.53.2Your libraries and code are validated on it, and you need continuity while you test the next runtime
2.04.14.2 on the runtime reference pageYou want the newest Spark line for new builds, after testing your casts, merges and libraries on it

Verify against Microsoft Learn

Runtime lifecycle status and component versions are stated differently across pages. The lifecycle page assigns each runtime a stage (experimental preview, public preview, general availability, end of support announced, long-term support) and an end-of-support schedule; the runtime reference pages list Delta Lake versions, and at least one other page lists a different Delta minor version for runtime 2.0. Read Apache Spark runtime lifecycle in Fabric, Runtime 1.3 and Runtime 2.0 before you choose, and prefer a runtime whose stage is general availability for production layers.

Test behavior changes, not just versions

A new Spark major version can change defaults that your loads depend on, for example how invalid casts are handled when ANSI SQL mode is on. In a notebook on the candidate runtime, check spark.conf.get("spark.sql.ansi.enabled") and run your merge and cast tests against it before promoting. If publishing fails after a runtime change, remove or update the incompatible library or compute setting and publish again.

Create and publish an Environment

  1. Prepare the Spark properties file. Choose the variant from the next section and keep it in the repository next to the code.
  2. Create the item. In the layer workspace, select New item, choose Environment, and name it with the item convention, for example ENV_SALES_SLV_Spark.
  3. Select the runtime. On the Home tab, pick the runtime from the Runtime dropdown.
  4. Configure compute. Choose the pool and, if the workspace admin has enabled item-level compute customization, the driver and executor sizes. Add the Spark properties from your file.
  5. Add libraries. Add public libraries by name and version, or upload a custom wheel that holds the shared merge engine and helpers. Choose Full publish mode for anything pipelines and schedules will run.
  6. Save and publish. Save stages the change; Publish applies it. Only one publish can run at a time, and Libraries and Spark compute cannot be edited during a publish.
  7. Set it as the workspace default. In Workspace settings, open Data Engineering/Science, then Spark settings, then the Environment tab. Turn on Set default environment, select the environment and save.
  8. Verify. Run the verification cell below in a notebook and confirm the properties are applied.

Custom pools and item-level compute

Compute sizes in an Environment take effect only when a workspace admin turns on Customize compute configurations for items in the workspace's Pool settings. When it is off, the Compute section of environment items is disabled and every Spark job uses the workspace default pool.

Spark properties

Two variants cover the layers. Both are flat key and value pairs. The baseline sets the Parquet date and timestamp behavior; the merge-heavy variant adds two settings for merge-heavy and scan-heavy loads.

# Baseline Spark properties for every layer (flat key: value pairs).
# CORRECTED reads and writes old date and timestamp values as they are, with no calendar rebasing.
spark.sql.parquet.datetimeRebaseModeInRead: CORRECTED
spark.sql.parquet.datetimeRebaseModeInWrite: CORRECTED
spark.sql.parquet.int96RebaseModeInRead: CORRECTED
spark.sql.parquet.int96RebaseModeInWrite: CORRECTED
# Baseline properties plus two settings for merge-heavy and scan-heavy loads (Silver, and Gold loads that merge).
spark.sql.parquet.datetimeRebaseModeInRead: CORRECTED
spark.sql.parquet.datetimeRebaseModeInWrite: CORRECTED
spark.sql.parquet.int96RebaseModeInRead: CORRECTED
spark.sql.parquet.int96RebaseModeInWrite: CORRECTED
spark.microsoft.delta.merge.lowShuffle.enabled: 'true'
spark.sql.files.maxPartitionBytes: 512m
# Git representation of the Spark compute section (the Setting folder of the environment item).
runtime_version: '1.3'          # must match the runtime selected for the environment
spark_conf:
  spark.sql.parquet.datetimeRebaseModeInRead: CORRECTED
  spark.sql.parquet.datetimeRebaseModeInWrite: CORRECTED
  spark.sql.parquet.int96RebaseModeInRead: CORRECTED
  spark.sql.parquet.int96RebaseModeInWrite: CORRECTED
  spark.microsoft.delta.merge.lowShuffle.enabled: 'true'
  spark.sql.files.maxPartitionBytes: 512m
PropertyWhat it doesTrade-off
spark.sql.parquet.datetimeRebaseModeInRead and ...InWriteControls how DATE and TIMESTAMP values are read and written when files may come from older engines that used a hybrid Julian and Gregorian calendar. Modes: EXCEPTION (the default, fails on ambiguous old values), CORRECTED (no rebasing) and LEGACY (rebases)CORRECTED avoids failures on very old dates but will not shift values that a legacy writer stored under the old calendar. Choose it knowing which engines wrote your Bronze files
spark.sql.parquet.int96RebaseModeInRead and ...InWriteThe same choice for INT96 timestamps, an older Parquet timestamp encodingAs above
spark.microsoft.delta.merge.lowShuffle.enabledLow Shuffle Merge: avoids shuffling rows a MERGE does not change, which speeds up upserts where a small share of rows change and preserves the layout of untouched dataMatched and unmodified rows are written in separate jobs, which can produce more files; pair it with periodic OPTIMIZE and VACUUM
spark.sql.files.maxPartitionBytesTarget bytes of file data packed into one input partition on file reads; the Spark default is 128 MBLarger values mean fewer, bigger tasks and less scheduling overhead; they do not fix small-file sprawl and do not affect writes

Both key spellings are in circulation. Apache Spark documentation uses the names above, and the older spark.sql.legacy.parquet.* names appear in earlier material and are still accepted as alternative names in Spark 3.

Verify against Microsoft Learn

Two details need a check in your own tenant. First, the default value of the low shuffle merge property in your runtime: run spark.conf.get("spark.microsoft.delta.merge.lowShuffle.enabled") in a notebook before assuming it is on or off. Second, the import path for a Spark properties file: the migration guide describes uploading a properties file in the Spark properties section, while Add from .yml appears in the Public libraries section for the library file. See Migrate libraries and properties to a default environment and Compute management in Fabric environments. If the import dialog rejects the flat form, enter the properties manually or use the Git form.

Libraries and publish modes

Each runtime ships built-in libraries. The Environment adds public libraries from PyPI or Conda and custom libraries you build, which is where the shared merge engine and helpers belong. Package them as a wheel, version them, and attach them here so every notebook imports the same code; see Shared Libraries.

Publish modePublish timeSession startUse for
QuickAbout 5 secondsLibraries install when the session startsRapid iteration in development
FullTypically 3 to 6 minutesAdds about 1 to 3 minutes for dependency deployment; a custom live pool attached to the environment brings starts back to secondsPipelines, schedules and shared workloads, because it builds a stable, reproducible snapshot

Do not install libraries inline in scheduled runs

Inline %pip install is disabled by default for runs started from a pipeline or API, is not retained across runs and lets dependency versions drift between runs. Put the library in the Environment and use Full publish mode instead.

Attaching and inheriting

A notebook or Spark job definition can attach an Environment directly, or use Workspace default. With Set default environment off, Workspace default means the workspace-level Spark settings; with it on, Workspace default means the chosen environment item.

RuleConsequence
Switching an attached environment during an active sessionTakes effect only from the next session
Attaching an environment from another workspaceBoth workspaces must have the same capacity and the same network security settings; otherwise the session fails to start
Compute settings of a borrowed environmentIgnored; the pool and compute come from the current workspace
Sharing an environmentRecipients get Read permission by default, enough to attach it; grant Read on attached environments when you share notebooks
Deleting an environmentPermanent; attached items must be reconfigured, and a default environment must be changed first

In a strict isolation design, give every layer workspace its own environment and set it as default. Borrowing one environment across layer workspaces looks economical but binds layers together through capacity and network settings, which is the coupling the layer split exists to remove.

Git and deployment pipelines

TopicBehavior
What Git tracksLibraries (public as a YAML representation, custom with their source files) and the Spark compute section including runtime and properties. Resources are not included
Git syncLands in the staging state and does not take effect until published; publish after every sync, or call the Environment publish API
Deployment pipelinesDeploy the environment's contents to the next stage; the published state is preserved, so no extra publish is needed

Verify the environment

Run a short cell at the top of a smoke-test notebook in each environment and stage. It prints the Spark version and fails if any expected property is missing or different.

# Run in a notebook that uses the environment. Fails loudly if a property did not apply.
EXPECTED = {
    "spark.sql.parquet.datetimeRebaseModeInRead": "CORRECTED",
    "spark.sql.parquet.datetimeRebaseModeInWrite": "CORRECTED",
    "spark.sql.parquet.int96RebaseModeInRead": "CORRECTED",
    "spark.sql.parquet.int96RebaseModeInWrite": "CORRECTED",
    "spark.microsoft.delta.merge.lowShuffle.enabled": "true",
    "spark.sql.files.maxPartitionBytes": "512m",
}

print("Spark version:", spark.version)
mismatch = {}
for key, want in EXPECTED.items():
    got = spark.conf.get(key, "<unset>")
    print(f"{key} = {got}")
    if str(got).lower() != want.lower():
        mismatch[key] = got

assert not mismatch, f"Environment properties not applied: {mismatch}"
SymptomLikely causeFix
Properties are not appliedChanges saved but not published, or default environment not turned onPublish; check Set default environment in the workspace Spark settings
Publish failsA library or compute setting is incompatible with the selected runtimeRemove or update the incompatible item, then publish again
Session fails to start with a borrowed environmentCapacity or network security settings differ between the two workspacesCreate an environment in the current workspace
Slow session start after publishFull publish mode installs dependencies at startAttach a custom live pool, or reduce the library list
Library import works interactively but not in a pipeline runLibrary was installed inlineAdd it to the environment and publish in Full mode

Key takeaways

  • One Environment per layer workspace, set as the workspace default, replaces setup snippets in notebooks.
  • Pin the runtime on purpose, prefer a general availability runtime for production, and test casts and merges before changing it.
  • Publish in Full mode for anything scheduled; never install libraries inline in pipeline runs.
  • Verify the default values you depend on, such as low shuffle merge, with spark.conf.get instead of assuming them.
  • Git syncs land in staging and need a publish; deployment pipelines keep the published state but not custom pool references.
