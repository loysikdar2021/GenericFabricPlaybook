Generic full load with filters

full_load_overwrite is a full-replace (snapshot) loader: a safer CREATE TABLE AS SELECT written in PySpark, with guardrails, an optional filter, an optional transform, schema control and optional metrics. It extends the simpler full-load function for tables that need more than a filter.

from typing import Any, Callable, Dict, Mapping, Optional, Sequence, Union

from pyspark.sql import Column, DataFrame, SparkSession
from pyspark.sql import functions as F

RowFilter = Union[str, Column, Callable[[DataFrame], Column]]


def apply_row_filter(df: DataFrame, cond: Optional[RowFilter]) -> DataFrame:
    """Apply a SQL string, a Column, or a callable(df) -> Column."""
    if cond is None:
        return df
    if isinstance(cond, Column):
        return df.filter(cond)
    if isinstance(cond, str):
        return df.filter(F.expr(cond))
    if callable(cond):
        result = cond(df)
        if not isinstance(result, Column):
            raise TypeError("A callable row_filter must return a pyspark.sql.Column")
        return df.filter(result)
    raise TypeError("row_filter must be a SQL string, a Column or a callable(df) -> Column")


def full_load_overwrite(
    spark: SparkSession,
    source_table: str,
    target_table: str,
    *,
    row_filter: Optional[RowFilter] = None,
    transform_fn: Callable[[DataFrame], DataFrame] = lambda df: df,
    select_cols: Optional[Sequence[str]] = None,
    select_and_cast: Optional[Mapping[str, str]] = None,
    validate_required_cols: Sequence[str] = (),
    partition_by: Sequence[str] = (),
    num_repartitions: Optional[int] = None,
    overwrite_schema: bool = False,
    print_counts: bool = False,
) -> Dict[str, Any]:
    """Replace target_table with a filtered, transformed and typed snapshot of source_table."""
    if select_cols and select_and_cast:
        raise ValueError("Pass select_cols or select_and_cast, not both")

    # 1. Read and fail fast on missing columns (names compared case-sensitively).
    src = spark.table(source_table)
    missing = [c for c in validate_required_cols if c not in src.columns]
    if missing:
        raise ValueError(f"{source_table} is missing required columns {missing}")

    # 2. Filter early, then transform. transform_fn defaults to the identity function.
    out = transform_fn(apply_row_filter(src, row_filter))

    # 3. Projection: a declared, typed schema or a strict column list.
    if select_and_cast:
        out = out.select(*[
            (F.col(name) if name in out.columns else F.lit(None)).cast(dtype).alias(name)
            for name, dtype in select_and_cast.items()
        ])
    elif select_cols:
        absent = [c for c in select_cols if c not in out.columns]
        if absent:
            raise ValueError(f"Columns {absent} are not present after the transform")
        out = out.select(*select_cols)

    # 4. One overwrite commit: readers see the old snapshot or the new one, never a mix.
    if num_repartitions:
        out = out.repartition(num_repartitions)
    writer = out.write.format("delta").mode("overwrite")
    if overwrite_schema:
        writer = writer.option("overwriteSchema", "true")
    if partition_by:
        writer = writer.partitionBy(*partition_by)
    writer.saveAsTable(target_table)

    # 5. Optional metrics. Each count() is a full scan: development and bring-up only.
    metrics: Dict[str, Any] = {"source": source_table, "target": target_table}
    if print_counts:
        metrics["source_rows"] = src.count()
        metrics["target_rows"] = spark.table(target_table).count()
        print(metrics)
    return metrics

Semantics

  • Idempotent. The whole table is replaced in one Delta commit, so a retry produces the same result and readers never see a partial load.
  • Fail fast. Missing required columns, a missing projected column and a malformed filter all raise before anything is written.
  • Filter before transform. Rows the filter removes never reach the transform, which saves work and lets Spark push the predicate down to the file scan.

Usage: filters and projection

# Gold lakehouse notebook; slv is the shortcut schema that points at Silver.

# 1) Simple snapshot with an explicit column list
full_load_overwrite(
    spark, "slv.orders", "dbo.orders_snapshot",
    select_cols=["order_id", "customer_id", "order_ts", "status"],
)

# 2) Enforce a target schema across inconsistent sources: cast what exists, add the rest as typed NULLs
full_load_overwrite(
    spark, "slv.customers", "dbo.customers_curated",
    select_and_cast={
        "customer_id": "bigint",
        "email": "string",
        "loyalty_points": "bigint",
        "lifetime_value": "decimal(18,2)",
        "created_at": "timestamp",
    },
    validate_required_cols=["customer_id", "email"],
    overwrite_schema=True,
)

# 3) Filter only: a rolling seven-day snapshot
full_load_overwrite(
    spark, "slv.web_events", "dbo.web_events_7d",
    row_filter="event_ts >= date_sub(current_date(), 7)",
    print_counts=True,      # development only
)

Generalized examples

The original examples used three-part catalog names and a hard-coded calendar date in the filter. Fabric lakehouse notebooks address tables by schema and table name within the default lakehouse (or a four-part name across workspaces), and a fixed date in a production filter turns a rolling window into a shrinking one, so the examples use relative date functions.

Generic full load with transformation

The same function covers tables that need shaping. transform_fn is the injection point: pass a named function for anything you want to unit test, or a lambda for a single derived column. The type hint Callable[[DataFrame], DataFrame] means exactly that: a function that takes a Spark DataFrame and returns one.

from pyspark.sql import DataFrame
from pyspark.sql import functions as F


def open_orders(df: DataFrame) -> DataFrame:
    """Keep open orders and stamp the load time."""
    return (df.filter(F.col("status") == "open")
              .withColumn("loaded_at_utc", F.current_timestamp()))


# 1) Strict projection after a transform: fails if the transform dropped a column
full_load_overwrite(
    spark, "slv.orders", "dbo.open_orders",
    transform_fn=open_orders,
    select_cols=["order_id", "customer_id", "order_ts", "loaded_at_utc"],
)

# 2) Filter, transform and a partitioned target (only for tables large enough to justify partitions)
full_load_overwrite(
    spark, "slv.web_events", "dbo.web_events_90d",
    row_filter="event_ts >= date_sub(current_date(), 90)",
    transform_fn=lambda df: df.withColumn("event_date", F.to_date("event_ts")),
    partition_by=["event_date"],
    overwrite_schema=True,   # required if the partition columns differ from the existing table
)

# 3) Typed snapshot with a transform that derives a column the source lacks
full_load_overwrite(
    spark, "slv.customers", "dbo.customer_segments",
    transform_fn=lambda df: df.withColumn(
        "segment", F.when(F.col("lifetime_value") >= 10000, "premium").otherwise("standard")),
    select_and_cast={"customer_id": "bigint", "segment": "string", "lifetime_value": "decimal(18,2)"},
)

Silver incremental MERGE: line by line

This section explains incremental_merge_scd1 and its helpers as shown on the incremental loads page. The function slices increments with a prioritized watermark list, picks a key from candidate sets, filters early, keeps the latest row per key and applies one MERGE that updates non-key columns, inserts new keys and, when configured, deletes flagged keys.

Control flow

  1. Existence. Checks the target; raises if it is missing and create_if_missing is off.
  2. Mark. Uses watermark_value if given (string or datetime), otherwise derives it from the target. Subtracts lookback_minutes.
  3. Slice. build_slice filters first so predicates can be pushed down, then keeps rows with _wm above the mark.
  4. One aggregate pass. Counts rows, finds the new maximum watermark and counts null keys in a single job. The original ran head(1) and several counts.
  5. Early exit. An empty slice returns mode = "noop".
  6. Null keys. Fails, or drops them when on_null_key="drop". Keys are compared with =, not the null-safe <=> of the original, which matched NULL keys to each other and merged unrelated rows.
  7. Latest per key, split. Keeps one row per key, then splits rows matching delete_condition (as keys only) from upserts. The intermediate is persisted because it is read twice, and released in finally.
  8. Transform. Applies transform_fn to upserts only.
  9. Bootstrap. If the target does not exist, writes the upserts with errorifexists, so a concurrent creator is detected instead of overwritten.
  10. Align. Optional schema evolution, then aligns upserts and deletes to the target schema and tags them with _op U or D.
  11. MERGE. One statement with a conditional delete clause, an unconditional update clause and a conditional insert clause.
  12. Metrics. Reads inserted, updated and deleted counts from the commit.

Why the original delete never ran

The original built the MERGE as an unconditional update followed by an optional conditional delete. In Delta, when a MERGE has several matched clauses, only the last may omit its condition, and clauses are evaluated in order. With the update first the statement is either rejected or the delete is unreachable, depending on the version. The delete condition also referred to a column the row filter had already removed. The rewritten MERGE puts the conditional delete first.

Notes on the usage blocks

  • Grain first. Put the true grain first in key_candidates. A fallback key that is coarser than the grain (a product and date for a table whose grain also includes the store) merges distinct rows; prefer an error.
  • Filters and deletes. A filter such as "not deleted" belongs in Gold, or in delete_condition, not in row_filter; otherwise deleted rows never reach the MERGE.
  • Counts. count() is an exact full scan. The utility no longer counts source and target; use reconciliation on a schedule instead.

Gold engine: line by line

Constants and transforms

WATERMARK_COLS_DEFAULT is the update-timestamp priority list shared by all Gold tables. The engine coalesces these in order and takes the first non-null value as the row's last-changed time, which lets the pipeline slice only new and changed rows and survive tables that lack the preferred column. If upstream does not set the first column reliably, the engine will miss or repeat changes; keep the list, and push the source to set the first entry consistently.

Each transform turns Silver rows into the exact Gold shape: transform_fact_order_lines pivots the three charge slots into four named measures and computes gross and net amounts; transform_fact_orders derives an integer date key. Both end in an explicit select, so the Gold schema is stable and ordered. The original had two near-identical transforms for two facts; the slot logic is now one helper used in a loop.

TABLE_CONFIG

A dictionary from Gold table name to its settings: source, key candidates, transform, delete condition and the measures to reconcile. One generic function handles many tables without copied code; adding a table means adding an entry.

The two functions

Stepincremental_merge_with_qa
1Merges the table's configuration with any overrides passed to the call.
2Builds the shared arguments (filter, transform, delete condition, key normalization, tie-break) once, so the merge and the reconciliation use identical rules.
3Calls the Silver utility, which slices, deduplicates, transforms and merges.
4If run_qa, calls qa_reconcile and attaches the result under qa.
Stepqa_reconcile
1Builds the full source with build_slice and no mark, so every Silver row is considered.
2Keeps the latest row per key, removes rows matching the delete condition and applies the transform: the expected Gold content.
3Aggregates row count and the configured measure sums on the expected side and on the target in one pass each.
4Compares each pair with math.isclose, returns qa_ok and the per-check details, and raises if raise_on_mismatch.

Design features

  • Incremental by design: watermark slicing and latest-per-key selection.
  • Idempotent MERGE: safe to rerun; only changes after the mark, minus the lookback, are considered.
  • Loose coupling: each table's shape and grain live in configuration; the engine does not know which table it is loading.
  • Observable: merge metrics from the commit history and reconciliation results in one dictionary, ready for a run log table.

Key takeaways

  • Use full_load_overwrite when a snapshot needs filters, transforms or a declared schema; use the simple function when it does not.
  • In MERGE, put conditional matched clauses before the unconditional one, and never compare keys null-safely.
  • Read exact merge counts from the Delta commit instead of counting.
  • Keep session settings in the Environment, not inside utility functions.
