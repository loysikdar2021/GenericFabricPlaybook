Postures are a starting point for a security-conscious enterprise. Default shows only what the documentation states; a dash means the default is not stated, so capture your tenant's real values with the API snapshot before changing anything. Scope reads Groups when the documentation says the setting supports security groups and exceptions, and Org only when it applies to the entire organization. A dash in Scope means the documentation I checked does not say; many such settings do offer groups in the portal, and the canSpecifySecurityGroups field of the Get Tenant Settings API gives the authoritative answer for your tenant. Settings labeled preview carry a badge.

PostureReading
Enable for allLow-risk convenience features and guardrails.
Enable for specific groupsValuable but exposed: scope with an allow group and an exception group.
DisableLegacy, public, third-party-processing or preview features without an approved use case.
Decide per organizationDepends on network design, licensing or policy.

Where to start

If your tenant is still at its defaults, these ten changes remove the largest exposures first. Take the snapshot before the first change.

#ChangeWhy it comes first
1Snapshot every setting with the administration API.Gives you a baseline and a rollback for everything below.
2Publish to web: disable, then delete existing embed codes.Public, unauthenticated, and not retired by group scoping.
3Organization-wide shareable links: disable; keep the protected-label link guard on.Organization-wide links are hard to audit and spread easily.
4Service principal admin API switches (updates, read-only): dedicated groups only.Most privileged non-human identities in the tenant.
5Guest settings: switch off guest invitations, guest browsing and guests in suggested people; scope guest access to a group.Stops accidental external sharing.
6CSV export, download reports, XMLA and Analyze in Excel, Execute Queries API: specific groups with an exception group.Closes the bulk-extraction family together.
7External data sharing and accepting external shares: disable until a partner case exists.Cross-tenant data sharing where the consumer governs the data.
8Copilot: choose groups; keep the OpenAI subprocessor setting and the cross-geography settings off.Copilot is on by default.
9ArcGIS Maps, OneDrive and SharePoint viewing, Desktop link sharing and non-Entra Eventstream auth: disable.Organization-wide only, so no group scoping can help.
10Preview item types, Explore and UX experiments: disable; plan to retire Gen1 dataflows and datamarts.Unvetted features and legacy objects.

Verify against Microsoft Learn

Defaults, names and preview status change. Before you act on a row, confirm it on Tenant settings index and in your own portal. Where a setting exists in the portal but is not listed here, treat it as unreviewed and apply the decision framework before enabling it.

Key takeaways

  • Use the matrix as the review sheet: copy it, add your own decision, owner and date columns, and keep it with the snapshot.
  • Start with the ten changes that remove the biggest exposure, in order, after taking the snapshot.
  • Where a row says Org only, plan a compensating control because groups cannot help.
