AI, preview and experimental settings

Settings that govern Copilot and Azure OpenAI features, agents, preview item types, experiments, Microsoft 365 data sharing, and audit and usage reporting. These change fastest, so confirm status before widening access.

  • Portal groups Copilot, Microsoft Fabric, Explore, Audit and usage
  • Default stance Pilot groups, sandbox for preview
  • Verify Status changes often

Copilot and Azure OpenAI

Copilot features run on Azure OpenAI models and use the signed-in user's permissions to read data. Several independent switches decide whether a user gets them: the tenant setting, capacity settings, region settings and an optional subprocessor setting.

Users can use Copilot and other features powered by Azure OpenAI

Where
Copilot and Azure OpenAI Service
Default
On
Typical posture
Enable for specific groups — On by default, so a deliberate decision is needed.
Scope and delegation
Supports specific security groups and exceptions. Managed at tenant and capacity levels.
What it controls
Lets users use Copilot and Fabric AI agents and other Azure OpenAI powered features. Data agents depend on this setting. The service may run background jobs at no charge to the tenant capacity to support these experiences.
Risk or benefit
Prompts and context data are sent to the model service, and what a user can ask is bounded by their own permissions. Copilot consumption is billed to a capacity, and the results are only as good as the model metadata behind them.
Notes
Because it is on by default, deliberately choose who gets it: enable for pilot groups trained on prompting and data-handling rules, widen as policy matures. Capacity admins can enable or disable per capacity, which lets you place Copilot users on a dedicated capacity.

A rollout approach for Copilot

  1. Choose the capacity

    Designate a Copilot capacity (if you enable that setting) or choose an existing one so usage and billing are visible in one place.

  2. Create a pilot group

    Enable the tenant setting for a pilot allow group, and decide in advance what data-handling rules apply to prompts.

  3. Check the region settings

    If your capacity is outside the covered regions, decide whether the cross-geography processing and storage settings are acceptable. Keep them off until the answer is yes.

  4. Measure

    Review consumption in the Capacity Metrics app, review audit events and gather user feedback.

  5. Widen by group

    Broaden to more groups after training, and keep a clear process for turning features off quickly.

Verify against Microsoft Learn

Which Copilot and AI features are in preview, and which regions they support, changes often. Check the Copilot in Fabric overview and the feature-status page it links to before widening any group. Turning on the Azure OpenAI setting also accepts the preview terms for AI features in preview.

Two names for one group

The settings index lists this group as Copilot and Azure OpenAI Service, while the Copilot admin article calls it Copilot and AI and covers agents too. Look for the setting names rather than the group heading.

Agents

Fabric agents build on the same AI settings. Learn documents no separate tenant setting for data agents: they depend on the Copilot and Azure OpenAI setting and on Users can create Fabric items. The settings below govern what leaves the agent's boundary.

Agents can be consumed outside Fabric

Users can configure a data agent to be consumed from other services, such as Microsoft Foundry, Microsoft Copilot Studio, Microsoft 365 Copilot or an MCP server. Responses returned to those services can leave Fabric's compliance boundary or region and are handled under that service's terms. Decide who may publish agents before you enable the feature widely.

Exploration and experiments

Two organization-wide settings affect the interface people see rather than data paths. Both are easy to underestimate because they leak into training and support.

Users with view permission can launch Explore

Where
Explore settings
Status
Preview Labeled preview on Microsoft Learn.
Default
On — By default people with View permission can launch Explore.
Typical posture
Disable — Preview feature that widens ad hoc access for viewers.
Scope and delegation
Applies to the entire organization only; groups cannot be selected.
What it controls
Explore is a lightweight visual tool for ad hoc analysis without building a report. This setting lets people with only View permission on a semantic model launch it from the model and from connected items. If you turn the setting off, only users with Build permission can use Explore, and Lakehouses always need Build. Model owners can also restrict it per semantic model.
Risk or benefit
Viewers can query beyond the curated report, which strengthens agility and weakens consistency: different people may produce different numbers from the same model. Permissions and row-level security still apply.
Notes
Org-wide only. Disable until report-consumer governance, such as certified models, is ready.

Monitoring belongs in the standard

Tenant settings tell you what is allowed; usage metrics, the Purview audit log and capacity metrics tell you what happens. Decide the audit retention and who reviews it as part of the same standard.

Key takeaways

  • Copilot is on by default: choose who gets it deliberately, pilot first, and keep the subprocessor and cross-geography settings off until reviewed.
  • Data agents depend on the Copilot setting and Fabric item creation; there is no separate data-agent switch to rely on.
  • Keep preview item types off for the organization and enable them for a sandbox group.
  • Disable Explore and user-experience experiments until you can train and support what users will see.
  • Treat usage and query-text settings as privacy decisions and document the choice.
