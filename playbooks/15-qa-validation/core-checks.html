Playbook 15 · QA Validation

Harness and core checks

The notebook skeleton that every framework shares, followed by the four checks that give the broadest coverage for the least effort: row count, transformation, schema and freshness. Each check has its purpose, copy-ready code, success criteria and example output. Paste the cells into a notebook in order and they run as a complete standard suite.

Before you paste

The cells use a Contoso retail example (DEV_SALES_SLV to DEV_SALES_GLD). Attach a schema-enabled results lakehouse as the notebook's default lakehouse, create the tables from Results model and tolerances, and replace the workspace, lakehouse and table names in the configuration cell. The code targets Fabric Runtime 1.3 and later and does not depend on ANSI mode.

The notebook harness

Six cells, in this order. Cells 1 to 3 are the same in every framework; cell 4 holds the checks and is where frameworks differ; cells 5 and 6 run the suite, write results and return the exit value.

# ---- identifiers: configuration may only contain plain names ----------------------
_OBJECT_PART = re.compile(r"[A-Za-z0-9_][A-Za-z0-9_\- ]*")
_COLUMN = re.compile(r"[A-Za-z_][A-Za-z0-9_]*")

def quote_name(name: str) -> str:
    """'ws.lakehouse.schema.table' -> '`ws`.`lakehouse`.`schema`.`table`'."""
    parts = [p.strip().strip("`") for p in name.split(".")]
    if not 1 <= len(parts) <= 4 or not all(_OBJECT_PART.fullmatch(p) for p in parts):
        raise ValueError(f"Unsafe or malformed object name: {name!r}")
    return ".".join(f"`{p}`" for p in parts)

def col(name: str) -> str:
    if not _COLUMN.fullmatch(name):
        raise ValueError(f"Unsafe column name: {name!r}")
    return f"`{name}`"


# ---- temporary views: unique names, always dropped ---------------------------------
@contextmanager
def temp_views(**selects: str):
    """Create session-scoped temp views from SELECT statements; yield their names."""
    suffix = uuid.uuid4().hex[:10]
    names = {alias: f"qa_{alias}_{suffix}" for alias in selects}
    try:
        for alias, select_sql in selects.items():
            spark.sql(f"CREATE OR REPLACE TEMPORARY VIEW {names[alias]} AS {select_sql}")
        yield names
    finally:
        for name in names.values():
            spark.catalog.dropTempView(name)

def one_row(sql: str) -> dict:
    return spark.sql(sql).first().asDict()

def num(x) -> Optional[float]:
    return None if x is None else float(x)


# ---- result type and evaluator --------------------------------------------------------
@dataclass
class Result:
    test_name: str
    check_type: str
    status: str = "ERROR"
    severity: str = "blocker"          # blocker | warning | info
    source_object: Optional[str] = None
    target_object: Optional[str] = None
    rule: str = "eq"                   # eq | le | ge
    expected: Optional[float] = None
    actual: Optional[float] = None
    variance: Optional[float] = None
    variance_pct: Optional[float] = None
    tolerance: float = 0.0
    tolerance_type: str = "absolute"   # absolute | percent
    fail_threshold: Optional[float] = None
    message: str = ""
    detail: Optional[str] = None       # JSON text: samples, column lists
    duration_s: Optional[float] = None

def evaluate(r: Result) -> Result:
    """Fill variance and status from expected, actual, rule and tolerances."""
    if r.expected is None or r.actual is None:
        r.status, r.message = "ERROR", r.message or "expected or actual value is missing"
        return r
    r.variance = r.actual - r.expected
    r.variance_pct = None if r.expected == 0 else 100.0 * r.variance / abs(r.expected)
    breach = {"eq": abs(r.variance), "le": max(r.variance, 0.0), "ge": max(-r.variance, 0.0)}[r.rule]
    if r.tolerance_type == "percent":
        breach = breach / abs(r.expected) * 100.0 if r.expected else (0.0 if breach == 0 else float("inf"))
    if breach <= r.tolerance:
        r.status = "PASS"
    elif r.fail_threshold is not None and breach <= r.fail_threshold:
        r.status = "WARN"
    else:
        r.status = "FAIL"
    return r

Cell 3: check registry and runner

A check is a function that takes one configuration dictionary and returns a Result or a list of them. The decorator registers it under its check_type. The runner turns any exception into an ERROR result, runs independent checks in parallel, and runs checks that declare depends_on only if the check they depend on passed (one level of dependency is supported).

CHECKS = {}

def check(check_type: str):
    def register(fn):
        CHECKS[check_type] = fn
        return fn
    return register

def new_result(cfg: dict, **values) -> Result:
    fields = dict(
        test_name=cfg.get("test_name", "<unnamed>"), check_type=cfg.get("check_type", "<unknown>"),
        severity=cfg.get("severity", "blocker"),
        source_object=cfg.get("source"), target_object=cfg.get("target"),
        rule=cfg.get("rule", "eq"), tolerance=float(cfg.get("tolerance", 0.0)),
        tolerance_type=cfg.get("tolerance_type", "absolute"),
        fail_threshold=None if cfg.get("fail_threshold") is None else float(cfg["fail_threshold"]),
    )
    fields.update(values)
    return Result(**fields)

def run_check(cfg: dict) -> list:
    started = time.time()
    try:
        out = CHECKS[cfg["check_type"]](cfg)
        results = out if isinstance(out, list) else [out]
    except Exception as exc:     # a check that cannot run is an ERROR, never a PASS
        results = [new_result(cfg, status="ERROR", message=f"{type(exc).__name__}: {str(exc)[:400]}")]
    elapsed = round(time.time() - started, 2)
    for r in results:
        r.duration_s = elapsed
    return results

def run_parallel(configs: list) -> list:
    if not configs:
        return []
    if max_workers > 1:
        with ThreadPoolExecutor(max_workers=max_workers) as pool:
            batches = list(pool.map(run_check, configs))
    else:
        batches = [run_check(c) for c in configs]
    return [r for batch in batches for r in batch]

def run_suite(selected: list) -> list:
    independent = [c for c in selected if not c.get("depends_on")]
    dependent = [c for c in selected if c.get("depends_on")]
    results = run_parallel(independent)
    status_of = {r.test_name: r.status for r in results}
    runnable = []
    for cfg in dependent:
        dep_status = status_of.get(cfg["depends_on"], "MISSING")
        if dep_status not in ("PASS", "WARN"):
            results.append(new_result(cfg, status="SKIPPED",
                                      message=f"dependency {cfg['depends_on']} is {dep_status}"))
        else:
            runnable.append(cfg)
    return results + run_parallel(runnable)

def load_config_from_table(suite_name: str) -> list:
    rows = (spark.table(f"{results_schema}.validation_config")
                 .where(F.col("enabled") & (F.col("suite") == suite_name))
                 .collect())
    configs = []
    for r in rows:
        cfg = {k: v for k, v in r.asDict().items() if v is not None and k != "params"}
        cfg.update(json.loads(r["params"] or "{}"))
        for key in ("source", "target"):          # names are stored with an {env} token
            if key in cfg:
                cfg[key] = cfg[key].replace("{env}", env)
        configs.append(cfg)
    return configs

Configuration is executable

Filters and expressions in the configuration are inserted into SQL as written. quote_name and col constrain object and column names, but a filter such as order_status <> 'VOID' is trusted SQL. Treat the configuration (and especially the control table) like code: restrict who can change it, review changes and keep an audit trail.

Row count validation

Purpose

Confirm that the target holds exactly the rows the transformation is supposed to keep. It is the cheapest check, catches the largest class of defects (truncated loads, failed merges, join fan-out and fan-in, unintended filters) and should be on every table.

Implementation

Both sides are defined as temporary views so that optional filters apply to each relation once. One statement counts both, so the two numbers come from one planning step. The min_rows guard exists because 0 = 0 passes an equality check: an empty source and an empty target are consistent and almost always wrong.

@check("rowcount")
def rowcount(cfg):
    with temp_views(
        src=f"SELECT * FROM {quote_name(cfg['source'])} WHERE {cfg.get('source_filter', 'TRUE')}",
        tgt=f"SELECT * FROM {quote_name(cfg['target'])} WHERE {cfg.get('target_filter', 'TRUE')}",
    ) as v:
        row = one_row(f"""
            SELECT (SELECT COUNT(*) FROM {v['src']}) AS expected,
                   (SELECT COUNT(*) FROM {v['tgt']}) AS actual""")
    r = evaluate(new_result(cfg, expected=num(row["expected"]), actual=num(row["actual"]),
                            message=f"source={row['expected']:,} target={row['actual']:,}"))
    min_rows = cfg.get("min_rows")
    if min_rows is not None and r.expected is not None and r.expected < min_rows:
        r.status, r.message = "FAIL", r.message + f" (fewer than min_rows={min_rows})"
    return r

Success criteria

  • Target count equals the source count after the stated filters (or the tolerance in the configuration).
  • Both relations have at least min_rows rows when the guard is set.
  • No technical error reading either table.

Example output

test_name               status  expected  actual  variance  message
dim_customer.rowcount   PASS    18204     18204   0         source=18,204 target=18,204
fact_orders.rowcount    FAIL    1204331   1204299 -32       source=1,204,331 target=1,204,299

When the count is off, find the rows

A failing count is a symptom. Put a second, dependent check behind it that anti-joins on the business key (LEFT ANTI JOIN in Spark SQL) and stores a sample of missing keys in detail. Troubleshooting has the diagnostic queries.

Transformation validation

Purpose

Prove that a derived column in the target equals the expression applied to the source, for every row. Typical cases are concatenated labels, code-to-description mappings, trimmed or case-normalized text, and simple arithmetic.

Implementation

The check restates the transformation as a SQL expression over the source, then joins the result to the target on the business key and counts three kinds of disagreement. Casting both sides to text makes the comparison independent of numeric types; use the metric reconciliation check when you need tolerance on numbers.

@check("transformation")
def transformation(cfg):
    keys = [col(k) for k in cfg["key"]]
    key_list = ", ".join(keys)
    key_select = ", ".join(f"coalesce(s.{k}, t.{k}) AS {k}" for k in keys)
    on = " AND ".join(f"s.{k} <=> t.{k}" for k in keys)
    target_col = col(cfg["target_column"])
    with temp_views(
        src=(f"SELECT {key_list}, 1 AS _present, CAST(({cfg['expected_expr']}) AS STRING) AS expected_value "
             f"FROM {quote_name(cfg['source'])} WHERE {cfg.get('source_filter', 'TRUE')}"),
        tgt=(f"SELECT {key_list}, 1 AS _present, CAST({target_col} AS STRING) AS actual_value "
             f"FROM {quote_name(cfg['target'])} WHERE {cfg.get('target_filter', 'TRUE')}"),
    ) as v:
        join = f"FROM {v['src']} s FULL OUTER JOIN {v['tgt']} t ON {on}"
        c = one_row(f"""
            SELECT count_if(t._present IS NULL) AS missing_in_target,
                   count_if(s._present IS NULL) AS missing_in_source,
                   count_if(s._present IS NOT NULL AND t._present IS NOT NULL
                            AND NOT (s.expected_value <=> t.actual_value)) AS value_mismatches,
                   count_if(t._present IS NOT NULL AND t.actual_value IS NULL) AS null_targets
            {join}""")
        violations = int(c["missing_in_target"] + c["missing_in_source"] + c["value_mismatches"])
        sample = []
        if violations:                       # views are dropped on exit, so sample inside the block
            sample = [row.asDict() for row in spark.sql(f"""
                SELECT {key_select}, s.expected_value, t.actual_value {join}
                WHERE t._present IS NULL OR s._present IS NULL
                   OR NOT (s.expected_value <=> t.actual_value)
                LIMIT 5""").collect()]
    return evaluate(new_result(
        cfg, expected=0.0, actual=float(violations),
        message=(f"missing_in_target={c['missing_in_target']} missing_in_source={c['missing_in_source']} "
                 f"value_mismatches={c['value_mismatches']} null_targets={c['null_targets']}"),
        detail=json.dumps({"counts": c, "sample": sample}, default=str)))

When a table has no usable business key (a small reference table, for example), compare the expected and actual values as multisets instead. EXCEPT ALL keeps duplicates, so a value that appears twice in the expectation and once in the target is reported. This is also the cheapest way to debug a failing keyed check by hand.

-- rows the transformation should have produced but the target does not contain
SELECT concat(customer_code, ' - ', customer_name) AS v
FROM `DEV_SALES_SLV`.`LH_SALES_SLV`.`dbo`.`customers`
EXCEPT ALL
SELECT customer_label AS v
FROM `DEV_SALES_GLD`.`LH_SALES_GLD`.`dbo`.`dim_customer`;

-- rows in the target that no source row explains: swap the two SELECTs

Success criteria

  • The target column exists (a missing column surfaces as an ERROR, and the schema check says which one).
  • No key is missing on either side and no value differs.
  • The target column has no unexpected NULLs: null_targets is reported so a NULL that the expression would not produce is visible.
  • The expression in the configuration matches the specification, not the implementation. If you copy the pipeline's own code into the check you are testing the pipeline against itself.

Example output

test_name           status  expected  actual  message
dim_customer.label  PASS    0         0       missing_in_target=0 missing_in_source=0 value_mismatches=0 null_targets=0
dim_customer.label  FAIL    0         5       missing_in_target=2 missing_in_source=0 value_mismatches=3 null_targets=0

Schema validation

Purpose

Confirm that the columns downstream consumers depend on are present with the expected types. A renamed or retyped column breaks semantic models and reports without touching a single row count, so this is the check that catches contract drift between teams.

Implementation

The check reads the table's schema from the catalog and Delta log, so it does not scan data and costs almost nothing. Names are compared case-insensitively. Types are compared when the configuration states one. With strict set, columns that are not in the contract are reported too; leave it off for tables that are allowed to grow.

@check("schema")
def schema_contract(cfg):
    expected = {c["name"].lower(): (c.get("type") or "").lower() for c in cfg["columns"]}
    fields = spark.table(quote_name(cfg["target"])).schema.fields      # metadata only
    actual = {f.name.lower(): f.dataType.simpleString().lower() for f in fields}
    missing = sorted(set(expected) - set(actual))
    mistyped = {c: {"expected": t, "actual": actual[c]}
                for c, t in expected.items() if t and c in actual and actual[c] != t}
    unexpected = sorted(set(actual) - set(expected)) if cfg.get("strict") else []
    violations = len(missing) + len(mistyped) + len(unexpected)
    return evaluate(new_result(
        cfg, expected=0.0, actual=float(violations),
        message=f"{len(expected)} columns in contract, {violations} violation(s)",
        detail=json.dumps({"missing": missing, "mistyped": mistyped, "unexpected": unexpected})))

Success criteria

  • Every contracted column exists in the target.
  • Every contracted type matches (when stated).
  • With strict, no uncontracted columns exist.
  • Derived columns that were added by transformation logic (flags, labels, sort keys) are part of the contract, not an afterthought.

Example output

test_name            status  expected  actual  message                                  detail
dim_customer.schema  FAIL    0         2       3 columns in contract, 2 violation(s)    {"missing": ["customer_label"], "mistyped": {"customer_id": {"expected": "bigint", "actual": "int"}}, "unexpected": []}

Generate contracts, do not type them

For wide tables, generate the column list once from the approved table (spark.table(...).schema), review it, and commit it. Typing 35 column names by hand introduces its own defects. If a semantic model reads the table, the contract is the list of columns the model uses.

Freshness validation

Purpose

Confirm that data arrived on time. A pipeline can succeed, counts can match and the data can still be a day old because a source stopped delivering. Freshness is also the check that turns "the load ran" into "the data is current".

Implementation

The check computes the age of the newest value in a timestamp column, in hours, and compares it with a limit. It is a le check: expected is the allowed age, actual is the observed age, and only an older table breaches. A fail_threshold adds a WARN band so that the team hears about a late load before consumers do.

@check("freshness")
def freshness(cfg):
    ts = col(cfg["timestamp_column"])
    row = one_row(f"""
        SELECT timestampdiff(MINUTE, MAX({ts}), current_timestamp()) / 60.0 AS age_hours,
               count_if({ts} IS NULL)                                      AS null_timestamps,
               COUNT(*)                                                    AS row_count
        FROM {quote_name(cfg['target'])}""")
    if row["age_hours"] is None:
        return new_result(cfg, status="ERROR",
                          message=f"no timestamps in {cfg['timestamp_column']} ({row['row_count']} rows)")
    limit = float(cfg["max_age_hours"])
    r = new_result(cfg, rule="le", expected=limit, actual=float(row["age_hours"]),
                   message=f"newest row is {float(row['age_hours']):.1f} h old (limit {limit:g} h)",
                   detail=json.dumps({"null_timestamps": row["null_timestamps"], "rows": row["row_count"]}))
    return evaluate(r)

Success criteria

  • The newest timestamp is within max_age_hours of the run (PASS), or within the WARN band (WARN).
  • The column has at least one non-NULL value; an all-NULL or empty column is an ERROR, not a pass.
  • NULL timestamps are counted and reported in detail; add a completeness check if any NULL is unacceptable.

Example output

test_name              status  rule  expected  actual  message
fact_orders.freshness  PASS    le    6         1.4     newest row is 1.4 h old (limit 6 h)
fact_orders.freshness  WARN    le    6         8.2     newest row is 8.2 h old (limit 6 h)

Freshness pitfalls

  • Time zones. current_timestamp() is an instant, and Spark compares instants. The risk is a column that stores local wall-clock time as if it were UTC. Store timestamps as UTC, and if a legacy column cannot be changed, document the offset next to the check.
  • Calendars. A 6-hour limit fails every weekend for a source that does not deliver on weekends. Pass max_age_hours from the pipeline, vary it by day, or schedule the suite only on delivery days.
  • Partial refreshes. A table can have fresh rows for one region and none for another. If that matters, group the freshness query by the partition-like column and report the stalest group.

    raise RuntimeError(f"QA gate BLOCKED: {blocking} blocking failure(s) in run {run_id}")

notebookutils.notebook.exit(json.dumps(summary))

The exit value is a small JSON document with counts and the gate. Do not put per-check detail in it; the details are in the results table. Orchestration, gating and reporting shows how the pipeline reads it.

T-SQL variant for a Warehouse

When the target is a Warehouse table, the same checks can run in the warehouse itself with T-SQL, for example from a Script activity or a T-SQL notebook. Three-part names work within one workspace; expose Silver tables from other workspaces through a OneLake shortcut first. Writing the results to a warehouse table is an INSERT; a lakehouse results table remains the better default because it feeds Direct Lake directly.

-- Row count: expected from a shortcut-backed lakehouse table, actual from the warehouse
SELECT (SELECT COUNT_BIG(*) FROM LH_HR_SLV.dbo.employees)     AS expected,
       (SELECT COUNT_BIG(*) FROM WH_HR_GLD.dbo.dim_employee)  AS actual;

-- Freshness: age in hours of the newest row (loaded_at stored as UTC datetime2)
SELECT DATEDIFF(MINUTE, MAX(loaded_at), SYSUTCDATETIME()) / 60.0 AS age_hours
FROM WH_HR_GLD.dbo.fact_workforce_fte;

-- Transformation: keyed comparison without EXCEPT ALL
SELECT COUNT_BIG(*) AS value_mismatches
FROM LH_HR_SLV.dbo.employees AS s
JOIN WH_HR_GLD.dbo.dim_employee AS t ON t.employee_id = s.employee_id
WHERE t.employee_label <> CONCAT(s.employee_code, ' - ', s.employee_name);

Collation changes string comparisons

A new Warehouse defaults to a case-sensitive collation, as does a lakehouse SQL analytics endpoint, and Spark compares strings case-sensitively. A transformation that lower-cases text can pass in one engine and fail in the other if the collations differ. Compare in the engine that produced the target, or apply an explicit COLLATE in the check.

Key takeaways

  • One small harness (parameters, helpers, registry, configuration, runner, writer, exit) serves every framework; only the checks differ.
  • Row count, keyed transformation, schema contract and freshness cover most defects at low cost; give every table a row count, schema and freshness check.
  • Use a minimum-rows guard, a keyed comparison and a source-side timestamp so that checks cannot pass on empty, duplicated or stale data.
  • Treat configuration as executable code, and run uniqueness before keyed comparisons so failures point at the root cause.
  • Keep the exit value to a compact summary and the evidence in the results table.
