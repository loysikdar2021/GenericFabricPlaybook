Appendix: collecting IDs and rule values

Deployment rules need workspace IDs, item IDs and SQL connection strings for every target stage. Collecting them by hand from URLs invites typos. This appendix collects them programmatically into a table and gives a template to record what you configured.

Inventory notebook

Run this PySpark notebook from a lakehouse you can write to. It lists the workspaces whose names match a pattern, reads the lakehouses, warehouses, semantic models and notebooks in them, adds the SQL endpoint details for lakehouses and warehouses, and writes the result to Delta tables with a prefix.

  • The running identity needs at least Viewer on each workspace it reads. It sees only workspaces it has access to.
  • The notebook obtains a token with notebookutils.credentials.getToken("pbi"). Valid audiences are storage, pbi, keyvault and kusto; arbitrary resource URLs are not accepted. A service principal token obtained this way can have limited scopes, so run the notebook as a user for the broadest view.
  • List endpoints are paged. The helper follows continuationToken until the list is complete, and honours Retry-After when throttled.
import re
import time

import notebookutils
import requests
from pyspark.sql.types import StringType, StructField, StructType

FABRIC_API = "https://api.fabric.microsoft.com/v1"
WORKSPACE_NAME_PATTERN = r"^(DEV|TST|PRD)_SALES_"   # limit the scan to your platform's workspaces
TARGET_TYPES = {"Lakehouse", "Warehouse", "SemanticModel", "Notebook"}
TABLE_PREFIX = "fabric_"
SAVE_TO_LAKEHOUSE = True                            # needs a default lakehouse attached to this notebook

# Valid audiences: storage, pbi, keyvault, kusto. Never print or store the token.
HEADERS = {"Authorization": f"Bearer {notebookutils.credentials.getToken('pbi')}"}


def get_json(url, params=None, retries=5):
    """GET with retry on throttling (429) and transient server errors."""
    for attempt in range(1, retries + 1):
        resp = requests.get(url, headers=HEADERS, params=params, timeout=60)
        if resp.status_code == 429 or resp.status_code >= 500:
            time.sleep(int(resp.headers.get("Retry-After", min(10 * attempt, 60))))
            continue
        resp.raise_for_status()
        return resp.json()
    raise RuntimeError(f"GET {url} failed after {retries} attempts (last status {resp.status_code})")


def get_all(url, params=None):
    """Follow continuationToken until the list is complete."""
    rows, params = [], dict(params or {})
    while True:
        page = get_json(url, params)
        rows.extend(page.get("value", []))
        next_token = page.get("continuationToken")
        if not next_token:
            return rows
        params["continuationToken"] = next_token


workspaces = [w for w in get_all(f"{FABRIC_API}/workspaces") if re.search(WORKSPACE_NAME_PATTERN, w["displayName"])]
print(f"Workspaces matched: {len(workspaces)}")

COLS = ["workspaceName", "workspaceId", "itemType", "itemName", "itemId",
        "sqlEndpointId", "sqlConnectionString", "sqlProvisioningStatus", "error"]
records = []
for ws in workspaces:
    try:
        items = get_all(f"{FABRIC_API}/workspaces/{ws['id']}/items")
    except requests.HTTPError as err:
        print(f"Skipping {ws['displayName']}: {err}")
        continue
    for item in items:
        if item["type"] not in TARGET_TYPES:
            continue
        rec = dict.fromkeys(COLS)
        rec.update(workspaceName=ws["displayName"], workspaceId=ws["id"], itemType=item["type"],
                   itemName=item["displayName"], itemId=item["id"])
        try:
            if item["type"] == "Lakehouse":
                props = get_json(f"{FABRIC_API}/workspaces/{ws['id']}/lakehouses/{item['id']}").get("properties", {})
                sql = props.get("sqlEndpointProperties") or {}
                rec.update(sqlEndpointId=sql.get("id"), sqlConnectionString=sql.get("connectionString"),
                           sqlProvisioningStatus=sql.get("provisioningStatus"))
            elif item["type"] == "Warehouse":
                props = get_json(f"{FABRIC_API}/workspaces/{ws['id']}/warehouses/{item['id']}").get("properties", {})
                rec.update(sqlConnectionString=props.get("connectionString"))
        except requests.HTTPError as err:
            rec["error"] = str(err)
        records.append(rec)

schema = StructType([StructField(c, StringType(), True) for c in COLS])   # explicit: avoids NullType inference
inventory = spark.createDataFrame([tuple(r[c] for c in COLS) for r in records], schema)
inventory.createOrReplaceTempView("vw_fabric_inventory")
display(inventory.orderBy("workspaceName", "itemType", "itemName"))

if SAVE_TO_LAKEHOUSE:
    inventory.write.mode("overwrite").option("overwriteSchema", "true").saveAsTable(f"{TABLE_PREFIX}inventory")
    print(f"Saved table {TABLE_PREFIX}inventory")

Treat the output as internal

The table holds connection strings and IDs for every matched workspace. They are not secrets, but they describe your platform. Keep the table in a lakehouse with restricted access, do not commit notebook outputs to Git, and never add credentials to the notebook.

For a quick interactive look at a single workspace, sempy.fabric.list_items(workspace=...) from semantic link returns a DataFrame of the items in it, and needs at least Viewer access.

Queries for the rule values

Run these in a notebook cell with the SQL magic, in the lakehouse that holds fabric_inventory. Replace the workspace names with the target stage workspaces. Dataflow Gen2 creates staging lakehouses and warehouses that you must not use for rules, hence the exclusion.

Notebook default lakehouse rule

SELECT workspaceName, workspaceId AS lakehouseWorkspaceId, itemId AS lakehouseId, itemName AS lakehouseName
FROM fabric_inventory
WHERE itemType = 'Lakehouse'
  AND workspaceName IN ('TST_SALES_SLV', 'PRD_SALES_SLV')
  AND itemName NOT LIKE 'StagingLakehouse%'

Semantic model on a warehouse

SELECT workspaceName,
       sqlConnectionString AS server,
       itemName            AS databaseName,
       itemId              AS warehouseId
FROM fabric_inventory
WHERE itemType = 'Warehouse'
  AND workspaceName IN ('TST_SALES_CNSM_WH', 'PRD_SALES_CNSM_WH')
  AND itemName NOT LIKE 'StagingWarehouse%'

Use the database value in the same form the source stage shows in the rule's From field: the warehouse name, or its ID.

Semantic model on a lakehouse SQL endpoint (Direct Lake on SQL)

SELECT workspaceName,
       sqlConnectionString AS server,
       sqlEndpointId       AS databaseId
FROM fabric_inventory
WHERE itemType = 'Lakehouse'
  AND workspaceName IN ('TST_SALES_GLD', 'PRD_SALES_GLD')
  AND itemName NOT LIKE 'StagingLakehouse%'
  AND sqlProvisioningStatus = 'Success'

Verify against Microsoft Learn

Data source rules are supported for Direct Lake on SQL endpoints and not for Direct Lake on OneLake; see Direct Lake models. Confirm the property names returned by Get Lakehouse and Get Warehouse in the Lakehouse REST reference and Warehouse REST reference if the notebook returns empty values.

Record alongside the values: who owns the item (rules require the owner), the date of the last verification as <date> in your own record, and the deployment note that applied the rule.

Key takeaways

  • Collect IDs and connection strings programmatically; paging and throttling matter in tenants with many workspaces.
  • Use only the valid notebookutils token audiences, and run the inventory as a user if the service principal view is too narrow.
  • Exclude staging items, and enter database values in the form the rule's From field shows.
  • Keep a per-stage record of every rule so it can be recreated after an unassignment.
