Fabric definitions follow Microsoft Learn; where a capability's status or defaults change between releases, the linked page carries the verification note.

Naming tokens

Names such as DEV_SALES_SLV or NB_SALES_SLV_LoadCustomers follow the house grammar <ENV>_<DOMAIN>_<LAYER>[_<Qualifier>] for workspaces and <ARTIFACT>_<DOMAIN>_<LAYER>_<Function> for items. The full abbreviation tables are in Workspace pattern and naming; how the pieces fit is in the reference architecture.

A

Activator
A Fabric item that watches data (events, report visuals, Eventstreams) and runs an action, such as an e-mail, a Teams message or a pipeline run, when a condition is met. In the house naming convention its abbreviation is RFL.
See: 03 · Workspace pattern and naming
Admin portal
The Fabric administration surface where tenant settings, capacity settings, domains and audit options are managed. Only Fabric administrators can open the tenant settings it contains.
See: 16 · Overview and how settings work, 16 · Decision framework and rollout
ALM (application lifecycle management)
The practices that move a change from development to production in a controlled way. On Fabric this site combines Git integration for source control with deployment pipelines for promotion between DEV, TST and PRD workspaces.
See: 05 · Overview and ALM map, 07 · Deployment strategy
Audience (org app)
A child item of an org app that decides which sections and items a group of users sees and, by default, which items they are granted access to. Every org app has at least one audience.
See: 11 · Access, ALM and lifecycle, 11 · Concepts and choosing an app model
Auto compaction
A Delta write option that checks for small files after a commit and compacts them automatically. It repairs small-file problems after writes, while optimize write prevents them during the write.
See: 08 · Fabric layout features
Autobinding
The deployment pipeline behavior that reconnects a deployed item to the paired copy of its dependency in the target stage, for example a report to the test-stage semantic model. It works within a workspace (and for reports and models across pipelines at the same stage position); cross-workspace references, Direct Lake models and Dataflow Gen2 do not autobind.
See: 07 · Autobinding, 07 · Autobinding

B

Backward deployment
Deploying content from a later deployment pipeline stage to an earlier one, for example PRD to TST. The product allows it between adjacent stages; this site treats promotion as one-way by process and permissions.
See: 07 · The manual deployment
Branch out
The Fabric Git action that creates a new branch and connects it to a new or existing workspace in one step, producing a feature workspace. Its permissions requirements differ from connecting a pre-created workspace.
See: 05 · GitHub Flow for Fabric
Bronze layer
The raw medallion layer: source-shaped data, appended as it arrived with ingestion metadata and minimal technical changes, so every later layer can be rebuilt from it. Workspace pattern <ENV>_<DOMAIN>_BRZ.
See: 03 · Layers and strict isolation, 02 · Bronze layer patterns
Bursting
Capacity behavior that lets an operation use more compute than the SKU provides while it runs, so it finishes faster. The extra consumption is then spread over time by smoothing.
See: 01 · Strategy, licensing and capacity

C

Capacity
The pool of compute that Fabric workspaces are assigned to, sized by an F SKU. It is the unit of compute, billing and throttling, so workspace-to-capacity placement isolates workloads from one another.
See: 01 · Strategy, licensing and capacity, 03 · Workspace pattern and naming
Capacity Metrics app
The Microsoft-provided Power BI app that shows capacity utilization, smoothing, throttling and per-operation consumption. Install it early: it keeps a limited history, so export baselines you need.
See: 01 · Strategy, licensing and capacity
Capacity unit (CU)
The measure of Fabric compute. An F SKU number is its CU count (F64 = 64 CU), and every operation's consumption is reported in CU-seconds in the Capacity Metrics app.
See: 01 · Strategy, licensing and capacity
Change data capture (CDC)
Reading inserts, updates and deletes from a source database's change log instead of comparing full snapshots. It is the most precise change signal for incremental loads and the basis of Copy job CDC replication and mirroring.
See: 02 · Change tracking options
Change data feed (CDF)
A Delta table property (delta.enableChangeDataFeed) that records row-level changes between table versions, so a downstream layer can read only what changed in Silver or Gold rather than rescanning the table.
See: 02 · Change tracking options
CODEOWNERS
A GitHub file that maps path patterns to users or teams. When a pull request touches a matching path, the owners are requested as reviewers automatically; a ruleset can then require their approval before merge.
See: 17 · Overview and how it works, 17 · Creating the CODEOWNERS file, 17 · Fabric folders and enforcement
Connection reference
A variable library type that stores the ID of an external data connection, so each stage can use a different connection. It is a static pointer and does not rebind on deployment; check its release status before relying on it.
See: 09 · Concepts and anatomy
Consumption layer
The house layer after Gold that serves data in the shape each consumer needs: a Warehouse for T-SQL, semantic models for BI and a lakehouse of Gold shortcuts for AI/ML. Workspace pattern <ENV>_<DOMAIN>_CNSM[_WH|_SM|_LH].
See: 03 · Layers and strict isolation, 03 · Workspace pattern and naming
Control table
A Warehouse table whose rows describe the tasks a master pipeline must run (item IDs, task type, stage, order, active flag). Pipelines read it with Lookup and iterate with ForEach, so adding a task is an INSERT rather than a pipeline edit.
See: 10 · Framework design and decisions, 10 · Warehouse objects and seed data
Copy job
A Fabric item that moves data from a source into OneLake without building a pipeline, with bulk, incremental and CDC-based replication modes. It sits between mirroring (least control) and pipeline Copy activities (most control).
See: 02 · Change tracking options, 02 · Choosing the right tool

D

Data pipeline
The Fabric orchestration item (from the Data Factory experience) that runs activities such as Copy, Notebook, Lookup, ForEach and Invoke pipeline. Abbreviation PL.
See: 02 · Choosing the right tool, 10 · Build the master pipeline
Dataflow Gen2
The low-code Power Query item for ingestion and light transformation that writes to lakehouse, warehouse and other destinations. It does not autobind on deployment, so parameterize its sources and destinations. Abbreviation DFL.
See: 02 · Choosing the right tool, 07 · Autobinding
Deletion vectors
A Delta feature that marks rows as deleted instead of rewriting the whole file on DELETE, UPDATE or MERGE. Its default depends on the Fabric runtime version; OPTIMIZE purges them later.
See: 08 · Fabric layout features
Delivery layer
The house layer that exposes reports, paginated reports and apps to people (and APIs to systems) without exposing the data layers. Business users reach it through app audiences or item permissions, never workspace roles. Pattern <ENV>_<DOMAIN>_DLV.
See: 03 · Layers and strict isolation, 11 · Overview
Delta Lake
The open table format (Parquet files plus a transaction log) that Fabric uses for lakehouse and warehouse tables in OneLake. It provides ACID commits, time travel, MERGE and schema enforcement.
See: 08 · Why and when to partition, 02 · Silver: MERGE, SCD2 and deletes
Deployment pipeline
The Fabric feature that promotes item definitions between stage workspaces (typically DEV, TST, PRD), with compare, selective deploy, rules and history. It copies definitions, never data. This site uses one pipeline per layer, named DPLY_<DOMAIN>_<LAYER>.
See: 07 · Pipeline setup and pairing, 07 · Deployment order and layers
Deployment rule
A per-stage setting on a deployment pipeline that overrides a value during deployment, such as a semantic model's data source, a notebook's default lakehouse or a parameter. Rules take precedence over autobinding and are defined on the target stage.
See: 07 · Supported items and rules, 13 · Pipelines, gateways and sources
Direct Lake
A semantic model storage mode that loads columns from Delta tables in OneLake into memory on demand and queries them with the same engine as Import, without a scheduled import refresh. Its performance depends on the physical layout of the Delta tables.
See: 02 · Gold layer and Direct Lake, 12 · Semantic model standards
Direct Lake on OneLake
The Direct Lake variant that reads Delta tables directly from OneLake and never falls back to DirectQuery; exceeding a guardrail fails the refresh instead. It is the documented option for new models.
See: 02 · Gold layer and Direct Lake, 01 · Semantic models and reports
Direct Lake on SQL endpoints
The Direct Lake variant that reaches tables through a lakehouse SQL analytics endpoint or a warehouse. It can fall back to DirectQuery (controlled by the Direct Lake behavior property) when guardrails are exceeded or SQL-level security applies.
See: 02 · Gold layer and Direct Lake, 07 · Supported items and rules
DirectQuery
A storage mode in which every visual sends queries to the source at run time; no data is held in the model. In Direct Lake on SQL endpoints it is also the fallback path when Direct Lake cannot serve a query.
See: 12 · Semantic model standards
Dispatcher notebook
A notebook that runs another notebook by item ID instead of by name, so renames cannot break orchestration. The control-table framework uses it as its GUID launcher.
See: 10 · Notebook dispatcher (GUID launcher)
Domain
A Fabric grouping of workspaces by business area (for example SALES or FINANCE), used for delegated governance and discovery in the OneLake catalog. The <DOMAIN> token in workspace names should match it.
See: 01 · Governance with Fabric and Purview, 03 · Workspace pattern and naming

E

Endorsement
Labels that signal trust in an item: Promoted, Certified and Master data. Certification is restricted to authorized reviewers through a tenant setting.
See: 12 · Collaboration, endorsement and QA, 01 · Governance with Fabric and Purview
Environment (item)
A Fabric item that bundles a Spark runtime version, Spark properties, compute settings and libraries (including custom wheels), attached to notebooks and Spark job definitions or set as the workspace default. Abbreviation ENV.
See: 03 · The Environment item, 06 · Installing in a Fabric Environment
Eventstream
A Real-Time Intelligence item that captures, transforms and routes streaming events into destinations such as an Eventhouse or lakehouse. Abbreviation ES.
See: 03 · Workspace pattern and naming

F

F SKU
The Fabric capacity SKU family (F2 to F2048 and larger), purchased as an Azure resource that can be scaled and, on pay-as-you-go, paused. F64 and above remove the need for viewer Pro licenses for content on that capacity.
See: 01 · Strategy, licensing and capacity
Fabric REST API
The public API for workspaces, items, Git integration, deployment pipelines, environments and admin scanning. Automation in this site calls it from GitHub Actions or notebooks with a service principal.
See: 07 · Automation and limits, 10 · Asset discovery and inventory
fabric-cicd
An open-source Python library for code-first deployment of Fabric items from a Git repository into workspaces, with per-environment parameter replacement. An alternative or complement to deployment pipelines in CI.
See: 05 · Service principals and Actions, 07 · Automation and limits
Feature workspace
A short-lived developer workspace connected to a feature branch, where work in progress is built and tested before a pull request. Named after the source workspace with the work item as qualifier, for example DEV_SALES_BRZ_F1234.
See: 05 · GitHub Flow for Fabric
Framing
The Direct Lake refresh operation: a metadata-only step that points the model at the latest Delta table version. Incremental framing keeps resident column data whose files did not change, so append-style writes are cheaper than overwrites.
See: 02 · Gold layer and Direct Lake
Full load
Reloading an entire table on every run (truncate and reload, or overwrite). Simple and self-healing, it suits small tables and periodic integrity rebuilds but scales poorly and disturbs Direct Lake.
See: 02 · Full vs incremental loads

G

Git integration
The Fabric feature that connects one workspace to one branch and folder of a GitHub or Azure DevOps repository, and syncs item definitions with commit and update. It versions definitions, not data.
See: 05 · Overview and ALM map, 05 · Sync model and supported items
GitHub Flow
A branching model with one always-deployable main, short-lived feature branches and pull requests as the only way into main. Environments are reached by promotion, not by environment branches.
See: 05 · GitHub Flow for Fabric
Gold layer
The business-ready medallion layer: star-schema facts and dimensions, conformed keys and materialized derivations, laid out for Direct Lake and SQL reads. Pattern <ENV>_<DOMAIN>_GLD.
See: 03 · Layers and strict isolation, 02 · Gold layer and Direct Lake
Guardrails (Direct Lake)
Per-SKU limits on files, row groups and rows per table, plus model memory. On OneLake they fail the refresh when exceeded; on SQL endpoints they trigger fallback. Compaction keeps tables inside them.
See: 02 · Gold layer and Direct Lake, 08 · Patterns by layer and consumer

H

High watermark
An incremental-load pattern that stores the highest value of a monotonically increasing column (modified timestamp or sequence) and next time extracts only rows above it. It cannot see hard deletes.
See: 02 · Change tracking options, 03 · Overview
Hub and spoke
An orchestration pattern in which a master pipeline in a hub workspace (<ENV>_ORCH_HUB) invokes pipelines in spoke workspaces and owns order, retries and the run log.
See: 04 · Hub-and-spoke architecture, 04 · Overview
Hydration
Running the loads in a stage that has just received a deployment to populate its tables. A deployment copies definitions only, so each layer must be hydrated and verified before the next layer is deployed.
See: 07 · Deployment order and layers, 14 · Tips and watch-outs

I

Import mode
A storage mode that copies data into the semantic model on scheduled refresh. Fast and feature-complete, but it duplicates data and needs refresh windows.
See: 12 · Semantic model standards, 01 · Semantic models and reports
Incremental load
Loading only rows that changed since the last run, identified by a watermark, CDC or CDF, and applying them with append or MERGE. Cheaper at scale, but it needs keys, a reliable change signal and delete handling.
See: 02 · Full vs incremental loads, 02 · Silver: MERGE, SCD2 and deletes
Invoke pipeline activity
The pipeline activity that starts another pipeline, including one in a different workspace, and can wait for it to finish. Its legacy version supports same-workspace calls only.
See: 04 · The Invoke pipeline activity
Item pairing
The link a deployment pipeline keeps between an item in one stage and its counterpart in the next. Deployment overwrites the paired item; autobinding and compare depend on pairing, not on names.
See: 07 · Pipeline setup and pairing
Item reference
A variable library type that stores a workspace ID and an item ID, so each stage can point consumers at its own lakehouse, notebook or pipeline. Like a connection reference it is static and is not rewritten by deployment.
See: 09 · Concepts and anatomy, 04 · Logging, monitoring and CI/CD

L

Lakehouse
A Fabric item that combines a Tables area of Delta tables and a Files area in OneLake, read by Spark, a SQL analytics endpoint and Direct Lake. Abbreviation LH.
See: 03 · Layers and strict isolation, 08 · Patterns by layer and consumer
Liquid clustering
A Delta layout that clusters rows by up to four columns without partition directories and can be changed later. It is incompatible with partitioning and Z-Order on the same table; behavior and defaults differ by runtime.
See: 08 · Fabric layout features

M

Materialized lake view
A lakehouse object defined in Spark SQL that Fabric materializes and refreshes in dependency order, optionally with data-quality constraints. A declarative alternative to notebook transformations for some layer-to-layer steps.
See: 02 · Choosing the right tool, 15 · Comparison with other tools
Medallion architecture
Organizing data into layers of increasing quality: Bronze (raw), Silver (cleansed, conformed) and Gold (business-ready). This site adds Consumption and Delivery and isolates each layer in its own workspace.
See: 03 · Layers and strict isolation, Reference architecture
MERGE
A Delta (and T-SQL) statement that upserts a source set into a target by key in one atomic commit: update matched rows, insert new ones and optionally delete. The core of incremental Silver and Gold loads.
See: 02 · Silver: MERGE, SCD2 and deletes, 06 · Designing the library
Mirroring
Continuous, managed replication of a supported database (or catalog) into OneLake as Delta tables, without building pipelines. It replaces the ingestion step only; Silver and Gold logic still applies.
See: 02 · Change tracking options, 02 · Choosing the right tool
Monitoring hub
The Fabric page that lists runs of pipelines, notebooks, dataflows and other items across the workspaces you can access, with drill-down into activity runs.
See: 04 · Logging, monitoring and CI/CD, 10 · Operations, security and checklist

N

Notebook
A Fabric item for PySpark, Spark SQL, Scala, R or Python code, run interactively or from pipelines and schedules. Abbreviation NB.
See: 03 · Fabric notebooks
NotebookUtils
The built-in utility library for Fabric notebooks (successor to mssparkutils) for running other notebooks, reading variable libraries, credentials and file system operations.
See: 09 · Create and consume variables, 10 · Notebook dispatcher (GUID launcher)

O

OIDC federation
OpenID Connect trust between GitHub Actions and a Microsoft Entra app registration, so a workflow gets a short-lived token without a stored client secret.
See: 05 · Service principals and Actions, 06 · CI/CD with GitHub Actions
OneLake
The single, tenant-wide data lake behind every Fabric workload, provisioned automatically for each tenant. Every lakehouse and warehouse stores its tables in OneLake as Delta.
See: 03 · Layers and strict isolation, 16 · Workspaces, Git, OneLake and items
OneLake catalog
The Fabric discovery surface for items the user can access, with filters by domain, endorsement and item type, and governance views for owners.
See: 01 · Governance with Fabric and Purview, 11 · Overview
OneLake security
Role-based data access in OneLake that can scope reads to folders, tables, rows and columns, enforced by the engines that support it. Check which engines enforce it and its release status before relying on it for compliance.
See: 03 · Layers and strict isolation
OPTIMIZE
The Delta command that compacts small files into larger ones, optionally applying Z-Order or V-Order, and performs liquid clustering. It is itself a rewrite, so run it after loads in quiet windows.
See: 08 · Fabric layout features, 08 · Validation and operations
Optimize write
Pre-write compaction: Spark shuffles data into fewer, larger files before writing. Its default depends on the resource profile, and pipelines and dataflows do not inherit Spark session settings.
See: 08 · Fabric layout features
Org app
A Fabric item that packages reports, paginated reports, notebooks, real-time dashboards and other items from one workspace into a branded, multi-audience app, with access propagated to the included items. Several can exist per workspace.
See: 11 · Overview, 11 · Concepts and choosing an app model

P

Paginated report
A pixel-perfect, page-oriented report defined in RDL, designed for printing and export. Its data sources are not autobound by deployment pipelines and need data source rules.
See: 13 · Overview, 11 · Integrating Fabric and Power BI items
Partition pruning
Skipping whole partition folders when a query filters on the partition column. Useful only for large tables with a stable, low-cardinality filter column; otherwise partitioning creates small files.
See: 08 · Why and when to partition
PBIP
Power BI Project: a folder format that saves a report and its semantic model as text files (PBIR and TMDL), so they can be diffed and reviewed in Git.
See: 12 · Semantic model standards, 01 · Reverse-engineering legacy assets
PBIR
The enhanced Power BI report format: a folder of JSON files per page and visual, replacing the single legacy report JSON and making report changes reviewable.
See: 12 · Semantic model standards
Publish mode (Environment)
How an Environment installs libraries: Full mode builds a reproducible snapshot at publish time, Quick mode installs at every session start. Pipelines and scheduled jobs should use Full mode.
See: 06 · Installing in a Fabric Environment
Pull request
A GitHub request to merge a branch into another, where reviews, CODEOWNERS approval and status checks gate the change before it reaches main.
See: 05 · GitHub Flow for Fabric, 17 · Notifications and troubleshooting
Purview (Microsoft Purview)
Microsoft's governance and compliance suite. With Fabric it supplies sensitivity labels, data loss prevention, audit, the unified catalog, lineage and data-quality scanning.
See: 01 · Governance with Fabric and Purview, 15 · Comparison with other tools

R

Resource profile
A named set of Spark write defaults for a Fabric workspace or environment, such as writeHeavy (the default for new workspaces, V-Order off) and readHeavyForPBI (V-Order and optimize write on).
See: 08 · Fabric layout features
Ruleset
A GitHub repository or organization policy for branches and tags (required reviews, code-owner approval, status checks, blocked force pushes) with an explicit bypass list. Preferred over classic branch protection.
See: 05 · Access model and repository hardening, 17 · Fabric folders and enforcement
Run log
A table, usually in the control Warehouse, where every orchestration task writes its start, end, status and error. It answers "did last night's load finish?" in one query.
See: 04 · Logging, monitoring and CI/CD, 10 · Operations, security and checklist
Runtime (Fabric Runtime)
The versioned Spark, Delta, Python and library stack that notebooks and Spark job definitions run on, selected in the workspace settings or an Environment. Defaults for deletion vectors, clustering and file sizing differ by runtime.
See: 03 · The Environment item, 08 · Fabric layout features

S

SCD Type 2
Slowly changing dimension Type 2: keeping history by closing the current row (end date, current flag) and inserting a new version when tracked attributes change, usually with a MERGE.
See: 02 · Silver: MERGE, SCD2 and deletes, 01 · Build the data layers
Schema-enabled lakehouse
A lakehouse that supports multiple schemas (default dbo) for tables, enabling four-part names and schema-scoped shortcuts and security. This site keeps owned tables in dbo and upstream shortcuts in brz or slv.
See: 03 · Workspace pattern and naming
Semantic Link
A Python library (and the community extension semantic-link-labs) for reading and managing semantic models, reports and Fabric items from notebooks, used for inventory, rebinding and model analysis.
See: 12 · Rebinding reports to a new model, 01 · Reverse-engineering legacy assets
Semantic model
The Power BI model (formerly dataset) of tables, relationships, measures and security that reports query, in Import, DirectQuery or Direct Lake mode. Abbreviation SM.
See: 12 · Semantic model standards, 01 · Semantic models and reports
Sensitivity label
A Microsoft Purview Information Protection label applied to Fabric items that travels with exported data and can drive DLP and access policies.
See: 01 · Governance with Fabric and Purview, 16 · Content, models and discovery
Service principal
A Microsoft Entra application identity used by automation (CI/CD, orchestration connections, inventory). It needs the tenant setting that allows service principals to use Fabric APIs and explicit workspace roles.
See: 05 · Service principals and Actions, 16 · Integration, developer and APIs
Shortcut
A OneLake object that points to data in another OneLake location or an external store without copying it. Access is authorized at the target, and in this design shortcuts live downstream and point one layer up.
See: 03 · Layers and strict isolation, 03 · Workspace pattern and naming
Silver layer
The cleansed and conformed medallion layer: one validated, deduplicated version of each entity at source grain, without business-specific logic. Pattern <ENV>_<DOMAIN>_SLV.
See: 03 · Layers and strict isolation, 02 · Silver: MERGE, SCD2 and deletes
Smoothing
How a capacity spreads an operation's CU consumption over future time: interactive operations over minutes, background operations over 24 hours. It lets scheduled jobs start together without a spike; throttling starts only when future capacity is already committed.
See: 01 · Strategy, licensing and capacity
Spark job definition
A Fabric item that runs a Spark application from files (Python, JAR) on a schedule or from a pipeline, without a notebook UI. Abbreviation SJ.
See: 03 · Workspace pattern and naming
SQL analytics endpoint
The read-only T-SQL endpoint created automatically for every lakehouse, exposing its Delta tables as SQL tables and views. Its metadata sync can lag behind Spark writes.
See: 08 · Validation and operations, 15 · Architecture and design principles

T

Tenant settings
Fabric admin-portal switches that enable or restrict features for the whole organization or for specific security groups, with optional delegation to capacity and domain admins.
See: 16 · Overview and how settings work, 16 · Quick reference matrix
Thin report
A report with no model of its own that connects live to a shared semantic model. It separates report authoring from modeling and lets one certified model serve many reports.
See: 12 · Collaboration, endorsement and QA, 01 · Semantic models and reports
Throttling
Delays and then rejections of new requests when a capacity has already committed future CU beyond policy thresholds. Running operations are not stopped; interactive requests are delayed first, then rejected, then background work.
See: 01 · Strategy, licensing and capacity
TMDL
Tabular Model Definition Language: a human-readable text format for semantic model metadata, used in PBIP projects and Git integration.
See: 12 · Semantic model standards, 12 · Naming, DAX and measures tables

V

V-Order
A write-time Parquet optimization for faster reads by Fabric engines, especially Direct Lake. Off by default in new workspaces (writeHeavy profile); enable it for Gold tables read by Direct Lake.
See: 08 · Fabric layout features, 02 · Gold layer and Direct Lake
VACUUM
The Delta command that deletes files no longer referenced by the log and older than the retention period (seven days by default). It reclaims storage but limits time travel; it does not improve layout.
See: 08 · Fabric layout features
Value set
A named set of variable values in a variable library. The default value set always exists; alternative sets (for example TST, PRD) store only overrides. Exactly one set is active per workspace, and deployment does not change it.
See: 09 · Concepts and anatomy, 09 · Concepts and anatomy
Variable library
A Fabric item holding variables with a value set per stage, read at run time by pipelines, notebooks, dataflows, shortcuts and other consumers. Abbreviation VL.
See: 09 · Overview, 09 · Create and consume variables

W

Warehouse
The Fabric item for a full T-SQL (read and write) relational warehouse whose tables are Delta in OneLake. Its T-SQL surface differs from SQL Server, and its default collation is case-sensitive. Abbreviation WH.
See: 10 · Warehouse objects and seed data, 03 · Workspace pattern and naming
Wheel
The built Python package format (.whl). Shared Spark utilities are packaged as a versioned wheel and installed through an Environment so all notebooks import the same code.
See: 06 · Packaging and building a wheel, 06 · Installing in a Fabric Environment
Workspace
A Fabric container for items, assigned to one capacity, with its own roles, Git connection and deployment-pipeline stage. It is the isolation unit of the house pattern <ENV>_<DOMAIN>_<LAYER>.
See: 03 · Layers and strict isolation, 03 · Workspace pattern and naming
Workspace app
The classic Power BI app: one per workspace, a versioned copy updated by an explicit Update app step, with up to 25 audiences. Org apps coexist with it.
See: 11 · Concepts and choosing an app model
Workspace identity
An automatically managed service principal associated with a workspace, used for authentication and trusted access, for example to firewall-enabled storage through shortcuts or in pipeline connections.
See: 16 · Workspaces, Git, OneLake and items, 04 · The Invoke pipeline activity
Workspace roles
Admin, Member, Contributor and Viewer: the coarse access control on a workspace. Assign them to security groups per layer and never give business users a role in a data workspace.
See: 03 · Workspace pattern and naming, 05 · Access model and repository hardening

X

XMLA endpoint
The Analysis Services protocol endpoint of a semantic model on capacity, used by tools such as Tabular Editor and DAX Studio for read and (when enabled) write operations.
See: 16 · Integration, developer and APIs, 01 · Reverse-engineering legacy assets

Z

Z-Order
A Delta OPTIMIZE option that co-locates related values across files for file skipping. Columns are specified on every run, and it is incompatible with liquid clustering on the same table.
See: 08 · Fabric layout features
