The playbooks along the implementation lifecycle

The playbooks are written to be used on their own, but they share one set of conventions — workspaces named <ENV>_<DOMAIN>_<LAYER>, one workspace per medallion layer, Git for development and deployment pipelines for promotion — so they also read as one implementation. Click any box to open that playbook.

How to use this site

Start from a decision

Every playbook opens with when to use it, the outcomes it gives you and a map of its pages. Decision tables and pros/cons come before procedures.

Follow the mechanism

Diagrams show where data flows, which identity calls what and what changes between options — read them before the step-by-step pages.

Run it, then check it

Code is parameterized and copy-ready; checklists remember what you ticked in your browser. Search with / from any page.

Verify against Microsoft Learn

Fabric changes quickly. The playbooks were checked against Microsoft documentation when written, and anything volatile (preview status, limits, supported items, setting names) is flagged with a callout and a link. Confirm those before you rely on them.
